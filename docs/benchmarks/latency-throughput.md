# 推論レイテンシとスループット評価 (Latency and Throughput)

`sokuto` の最優先要件は、
エージェントループや基幹システムのインライン判定においてボトルネックとならない
**超低遅延(Sub-20ms)と高いスループット** の実現です。
本章では、
CPU 環境(Apple M-series / 物理 8 コア)における単一推論遅延、並列バッチ処理能力、物理コア並列制御の効果、
および大規模候補探索(Coarse-to-Fine)の実測データを開示します。

---

## 1. ベンチマーク測定入力データの仕様 (`crates/sokuto-cli/src/commands/benchmark.rs`)

レイテンシおよびスループットの測定は、
乱数テンソルではなく、実際の業務ユースケースを模した日本語入力プロンプトを用いて行われています。
各シナリオの State、Instructions、Criteria は
[`crates/sokuto-cli/src/commands/benchmark.rs`](../../crates/sokuto-cli/src/commands/benchmark.rs) に厳密に定義されています。

| シナリオ名            |         プリミティブ / 候補数         | 入力コンテキスト (State)                                                                      | 評価指示文 (Instructions)                                           | 候補選択肢群 (Criteria)                                                                                                                          |
| :-------------------- | :-----------------------------------: | :-------------------------------------------------------------------------------------------- | :------------------------------------------------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Single Choice**     |          **Choice** ($K=3$)           | `顧客から注文キャンセルのリクエストを受信しました。注文ステータスは発送準備中です。` (41文字) | `適切な対応を選択してください。`                                    | 1. `cancel_order`: 注文を直ちにキャンセルする<br />2. `contact_support`: サポート窓口へ転送する<br />3. `ignore`: 特に対処せず保留する           |
| **Single Score**      |           **Score** ($K=5$)           | `過去 5 分間に不正なパスワード試行が同一 IP アドレスから 200 回検知されました。` (45文字)     | `セキュリティ脅威の深刻度を段階評価してください。`                  | 1. 極めて安全 (影響なし)<br />2. 低リスク (要注視)<br />3. 中リスク (調査推奨)<br />4. 高リスク (要即時対応)<br />5. 致命的インシデント (全遮断) |
| **Single Noul**       |          **Noul** (二値判定)          | `サーバーの CPU 使用率が 98%、空きメモリが 50MB 未満です。` (36文字)                          | `直ちにアラートを発報すべき緊急事態ですか？`                        | 真偽二値判定 (`true` / `false`)                                                                                                                  |
| **Batch Scaling**     | **Choice** (並列バッチ $Q=4, 8, 16$)  | `ユーザーが新規アカウント登録を行い、プロファイル情報を入力しました。` (34文字)               | 各質問 $i \in [0, Q)$:<br />`質問項目 {i} の判定を行ってください。` | 各質問 3 候補:<br />1. `approve_{i}`: 承認する<br />2. `review_{i}`: 審査に回す<br />3. `reject_{i}`: 却下する                                   |
| **Coarse-to-Fine**    |          **Choice** ($K=77$)          | `ATM から現金を引き出そうとしたところ、カードが取り込まれて返却されませんでした。` (42文字)   | `問い合わせの意図を分類してください。`                              | 1. `category_00` 〜 77. `category_76` (計 77 候補)<br />(Coarse スコアラーによる Top-16 粗スクリーニング → 精密モデル推論)                       |
| **Scratchpad 再利用** | **Choice** (メモリ再利用バッチ $Q=8$) | `注文履歴の確認と配送日時の変更手続きを受け付けました。` (27文字)                             | 各質問 $i \in [0, 8)$:<br />`変更可否を判定してください。`          | 各質問 2 候補:<br />1. `allow`: 変更を許可する<br />2. `deny`: 変更を拒否する                                                                    |

## 2. CPU 単一推論レイテンシ

上記プロンプトに対する、ONNX Runtime (CPU) インプロセス直接呼び出し時のレイテンシ実測値(ミリ秒)

(500 回の反復測定(ウォームアップ 10 回)から算出した確定値です。)

| プリミティブ      | モデル構成             | 最小 (Min) | 平均 (Mean) | 中央値 (p50) | 90% (p90) | 99% (p99) | 単一スループット |         目標 (p50)          |
| :---------------- | :--------------------- | :--------: | :---------: | :----------: | :-------: | :-------: | :--------------: | :-------------------------: |
| **Choice (K=3)**  | **Tier 1 (130M-INT8)** |  12.35 ms  |  12.61 ms   | **12.61 ms** | 12.74 ms  | 12.87 ms  |    79.3 dec/s    | $\le 20.0\text{ ms}$ (合格) |
|                   | **Tier 2 (310M-INT8)** |  22.42 ms  |  23.36 ms   | **23.28 ms** | 23.68 ms  | 24.44 ms  |    42.8 dec/s    | $\le 25.0\text{ ms}$ (合格) |
| **Noul (Binary)** | **Tier 1 (130M-INT8)** |  11.94 ms  |  12.22 ms   | **12.20 ms** | 12.37 ms  | 12.78 ms  |    81.8 dec/s    | $\le 15.0\text{ ms}$ (合格) |
|                   | **Tier 2 (310M-INT8)** |  21.81 ms  |  22.45 ms   | **22.45 ms** | 22.74 ms  | 23.21 ms  |    44.6 dec/s    | $\le 20.0\text{ ms}$ (合格) |
| **Score (K=5)**   | **Tier 1 (130M-INT8)** |  17.43 ms  |  18.04 ms   | **17.99 ms** | 18.19 ms  | 18.59 ms  |    55.4 dec/s    | $\le 20.0\text{ ms}$ (合格) |
|                   | **Tier 2 (310M-INT8)** |  32.48 ms  |  33.37 ms   | **33.26 ms** | 33.78 ms  | 35.87 ms  |    30.0 dec/s    | $\le 35.0\text{ ms}$ (合格) |

> [!NOTE]
> **LLM との速度差**
>
> クラウドの商用 LLM(GPT-4o mini や Claude 3.5 Haiku 等)は、
> ネットワーク往復およびトークン自己回帰生成により 500ms 〜 数秒 の遅延を要します。
> `sokuto` はローカル CPU 上で **12.2ms 〜 23.3ms** で確定するため、
> 約 **40 倍 〜 100 倍** 高速に確率決定を得ることができます。

## 3. 並列バッチスループット

複数の決定要求($Q$ 件)を動的マイクロバッチとして同時評価した際の実測スループット(反復 500 回)

(測定単位は **dec/s (Decisions Per Second: 1 秒あたりの確定決定数)** です。)

|      バッチサイズ ($Q$)       | Tier 1 遅延 (p50) |    Tier 1 スループット     | Tier 2 遅延 (p50) | Tier 2 スループット |
| :---------------------------: | :---------------: | :------------------------: | :---------------: | :-----------------: |
|       **1 (逐次実行)**        |     12.61 ms      |         79.3 dec/s         |     23.28 ms      |     42.8 dec/s      |
|             **4**             |     31.13 ms      |        128.5 dec/s         |     60.47 ms      |     65.8 dec/s      |
|             **8**             |     55.87 ms      |        142.3 dec/s         |     109.20 ms     |     72.8 dec/s      |
|            **16**             |     108.56 ms     |  **146.7 dec/s** (ピーク)  |     224.68 ms     |     71.0 dec/s      |
| **Scratchpad 再利用 ($Q=8$)** |   **50.78 ms**    | **156.9 dec/s** (最大効率) |   **103.07 ms**   |   **72.0 dec/s**    |

- **スループット向上**: バッチサイズ $Q=8 \sim 16$ で Tier 1 は **146.7 dec/s**、Tier 2 は **72.8 dec/s** を記録します。
- **Scratchpad テンソル再利用**: メモリアリーナを共有する `BatchScratchpad` を再利用することで、ヒープ再アロケーションが排除され、Tier 1 で **156.9 dec/s**(約 10% 高速化)を達成します。

## 4. 物理コア最適化 vs ハイパースレッディング (Thread Scaling)

ONNX Runtime の `intra_op_num_threads` 設定における、
**物理コア数固定 (8 スレッド)** と **論理コア全開 (16 スレッド)** の性能差の実測値です(200 反復)。

| 設定                                 | スレッド数 |  Choice p50  | Choice Throughput |  Score p50   |   Noul p50   |           判定           |
| :----------------------------------- | :--------: | :----------: | :---------------: | :----------: | :----------: | :----------------------: |
| **物理コア固定 (`intra-threads 8`)** |   **8**    | **12.63 ms** |  **79.2 dec/s**   | **17.96 ms** | **12.31 ms** |      ★ **最適性能**      |
| 論理コア全開 (`intra-threads 16`)    |     16     |   15.16 ms   |    65.3 dec/s     |   20.29 ms   |   14.59 ms   | ⚠️ **性能劣化 (-17.6%)** |

> [!NOTE]
> **背景コラム: 論理コア競合によるキャッシュ追い出し**
>
> 16 スレッド(論理コア全開)を指定した場合、
> 同一物理コア上の 2 つのハイパースレッドが L1/L2 データキャッシュを激しく追い出し合い、
> Choice レイテンシが **12.63ms → 15.16ms へ悪化**(スループットが **79.2 → 65.3 dec/s へ 17.6% 低下**)しました。
> `sokuto` のランタイムは起動時に `num_cpus::get_physical()` を参照し、
> デフォルトで物理コア数に固定する保護回路を備えています。

## 5. 大規模候補探索 (Coarse-to-Fine DAG) のレイテンシ特性

選択肢が 77 件に及ぶ高基数分類(Banking77 等)において、2 段階粗密探索(Coarse-to-Fine)を実行した際の実測値

| モデル                 | シナリオ       | 評価候補数 ($K$) | 平均遅延 (Mean) | 中央値 (p50) | スループット |
| :--------------------- | :------------- | :--------------: | :-------------: | :----------: | :----------: |
| **Tier 1 (130M-INT8)** | Coarse-to-Fine |     77 候補      |    39.10 ms     | **39.18 ms** |  25.6 dec/s  |
| **Tier 2 (310M-INT8)** | Coarse-to-Fine |     77 候補      |    78.79 ms     | **78.86 ms** |  12.7 dec/s  |

全候補(77 件)を一括してアテンション計算した場合(150ms 超)と比較し、
1 次スクリーニング(Coarse スコアラーによる Top-16 候補抽出)を行ってから 2 次精密推論を行うことで、
Tier 1 では **約 39ms** で 77 分類を完了します。

## 6. ベンチマーク再現手順

`sokuto` CLI を用いて、自身のマシンで実測値を再現するコマンド

```bash
# 1. 単一推論レイテンシの測定 (Tier 1: models/quantized)
./target/release/sokuto benchmark \
  --model-dir models/quantized \
  --scenario single \
  --warmup 20 \
  --iterations 200

# 2. 並列バッチスループットの測定 (Tier 1: models/quantized)
./target/release/sokuto benchmark \
  --model-dir models/quantized \
  --scenario batch \
  --warmup 10 \
  --iterations 100

# 3. 物理コア固定 (8) vs 論理コア全開 (16) の比較測定
./target/release/sokuto benchmark --model-dir models/quantized --scenario single --intra-threads 8 --iterations 200
./target/release/sokuto benchmark --model-dir models/quantized --scenario single --intra-threads 16 --iterations 200

# 4. 全シナリオ包括測定 (JSON 出力)
./target/release/sokuto benchmark --model-dir models/quantized --scenario all --iterations 500 --json > benchmark_results_tier1.json
./target/release/sokuto benchmark --model-dir models/modernbert-310m-int8 --scenario all --iterations 500 --json > benchmark_results_tier2.json
```
